# What a shared VisiMark link looks like — Implementation Plan

**Source:** `docs/reviews/2026-09-17-playground.md` §2.9 (row 9, Medium).

**Goal:** the four badge-share buttons stop producing bare blue links.

---

## What it looked like before

`shareViaClipboard()` opens Facebook, LinkedIn, Instagram and X with
`SHARE_URL = "https://michal-niedzwiedzki.github.io/visimark/"`. A grep of the
whole `docs/` tree for `og:` returned zero hits — and so did one for
`<meta name="description">`. Every network therefore rendered the link with
no title beyond the `<title>` tag, no summary, and no image. A visitor who
earns a badge is invited to share something that arrives looking like nothing.

## The decisions §2.9 asked for

### One tagline, not a third one

The review noted the two candidate taglines already differ between
`package.json`'s `description` and `index.html`'s subtitle, and asked for one
source of truth rather than a third copy.

**`packages/visimark/package.json`'s `description` is it.** It is already what
npm and the VS Code Marketplace show, so it is the string with the widest
existing reach, and `index.html`'s subtitle turns out to be its first clause
with the capital dropped — the same words, styled. So nothing had to be
rewritten, only wired:

- `<meta name="description">` and `og:description` on `index.html` are that
  field verbatim;
- `scripts/gen-og-image.mjs` reads the same field to letter the card;
- `test/social-cards.test.ts` fails if any of the three drift, allowing the
  subtitle only its lowercase styling.

The playground, tutorial and preview pages describe *themselves* rather than
repeating the product tagline — a card for the tutorial that says what the
site says is a card that tells a reader nothing about what they clicked.

### Own cards, shared image

Each page gets its own `og:title`, `og:description` and `og:url`, and they all
share one `og:image`. The image is the product's identity and does not change
per page; the words do.

`docs/og-card.png` is 1200 × 630, generated by `bun scripts/gen-og-image.mjs`
from the site's own palette and a real VisiMark snippet — the `vmark` block
computing `grand_total = SUM(Total)` and the prose value carrying
`<!--vmark=order.grand_total-->`, which is the product in two lines.

**The PNG is committed and deliberately not CI-guarded**, unlike `docs/vendor/`
and `docs/function-reference.md`. Two headless Chromiums of different versions
produce different bytes for identical input, so a `git diff --exit-code` gate
would fail on the runner's browser rather than on anything a person changed.
The generator's header says so, so the next person does not add the job and
then delete it.

### Per-badge cards: no

The review asked for this to be decided out loud rather than left open, and
guessed it was scope creep. It is. The share button knows which badge was
earned, but a card is read by a scraper that never runs JavaScript, so a card
per badge means a *static page* per badge for the scrapers to fetch — thirteen
generated pages and a build step, for a thumbnail. Declined, and the reason is
in the comment in `index.html` so that it stays declined.

### Absolute URLs

Every URL in every tag is absolute. A relative `og:image` is resolved against
the scraper rather than the page, so it fails by silently fetching nothing —
the same class of bug as the `vsix-readme-image-urls` note the review points
at. The test asserts this on all four pages rather than trusting review.

## Scope

Four pages, not the three the review named: `preview.html` is added because
`index.html` links to it five times, so it is as shareable as the rest. It
carries the generic site card on purpose — it renders whichever example
`?file=` names, and a scraper never runs the script that would know which.

## Verification

- `test/social-cards.test.ts`: each page carries a description, an
  `og:title`, a matching `og:description`, `summary_large_image`, an
  `og:image` that is the absolute card URL, `og:image:width`/`height`/`alt`,
  and an `og:url` that names *itself* — a copy-pasted block pointing at the
  wrong page is the likeliest mistake here and the hardest to see. It also
  reads `og-card.png`'s PNG header and checks the real pixel dimensions match
  what the tags promise, since a mismatch gets cropped differently by each
  network.
- The card was rendered and inspected at full size: the Caveat webfont
  arrives (the generator waits for it — without a virtual-time budget the
  screenshot lands first and the pitch line silently falls back to a
  sans-serif), the tagline sets on one line, and the snippet is legible at
  thumbnail scale.
- The playground still boots clean under its CSP with the new block in place
  (20 files, BUILD PASSING, no console output).
