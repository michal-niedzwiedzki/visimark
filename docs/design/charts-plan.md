# Generated artifacts (charts) — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to work this plan task-by-task. Steps are checkboxes for tracking.

**Goal:** Ship `chart <name> as pie|bar of <cols> labelled <col> [aspect w:h]` statements in `#id` sheet blocks, per [`docs/design/charts-spec.md`](charts-spec.md). `fmt` writes a deterministic SVG to the path the document's image line names; `check` proves it current by rendering and comparing bytes. A new `ARTIFACT` finding covers everything `fmt` cannot repair; `STALE` widens to cover an artifact that is out of date **or absent**. `explain` and `eval --json` surface charts; `infer` is untouched.

**Architecture:** A chart is a statement node that flows through the same pipeline as a binding and an assertion but stores nothing and produces no value. `chart` becomes a lexer keyword and `:` a new token (for `aspect`); `parseStatement` grows a third branch returning a `ChartDecl`. `model/build.ts` collects `ChartDecl`s onto their `Sheet`; a document-scope or table-less block carrying one is a `SHEET` finding, and a name colliding with a column or scalar is `DUP`. `parse/document.ts` gains `"image"` in `AnchorTargetKind` so an image node can carry an anchor — the anchor is never rewritten, it only associates the declaration with a path. `eval/graph.ts` adds one synthetic node per chart (`<sheetId>::chart@<offset>`), so a chart evaluates after its series and folds into the existing `unevaluable` / per-sheet `NOTE` machinery for free. `eval/check.ts` grows a chart branch: resolve the series and labels, hand them to the engine, compare the rendered bytes to disk. A new `src/artifact/` subsystem owns everything file-facing — `path.ts` is the §4 gate, `svg.ts` the emit primitives and monospace metrics, `stale.ts` the render-and-compare, `engines/` one file per engine behind a registry. Engines receive resolved data only (`{ series, labels, aspect }`) with no handle on the document, AST or evaluator, so a new engine is a registry entry plus one file. `write/fmt.ts` gains an artifact pass that writes whole files rather than splicing; the offset splicer is untouched and the document is never modified by chart generation. `packages/visimark-lsp/src/diagnostics.ts` carries a hardcoded code map and needs an `ARTIFACT` entry.

**Tech Stack:** TypeScript; `decimal.js` (numeric core); Bun test runner; engine package `packages/visimark`; LSP package `packages/visimark-lsp`; VS Code client `editors/vscode`.

**Spec:** [`docs/design/charts-spec.md`](charts-spec.md)

## Global Constraints

- Work on branch `issue/36-charts-impl` (draft PR #39). Do **not** open a new PR.
- `docs/example-invoice.md` and `docs/example-invoice-drift.md` stay **byte-for-byte identical**. The drift document's 26-problem [§13](../visimark-design.md#13-testing) transcript does not move. Charts get their own example document instead (Task 11).
- No new npm dependencies. The SVG is emitted as strings; there is no charting library.
- New `FindingCode` value `ARTIFACT`, added to `ERROR_CODES`. `STALE` widens in meaning only — it stays auto-fixable and keeps counting under "stale".
- `ARTIFACT` is **eight characters and fills the code field exactly**, the same case `COVERAGE` already carries in `report/format.ts`: its continuation lines indent to the head they follow, not to the shared `CONT` constant.
- **Determinism is the product.** No clock, no randomness, no network, no ambient fonts, no locally installed software may influence a byte of output. Any map iterated during emit must have a defined order.
- The SVG's metadata carries **nothing volatile** — no version, no timestamp, no absolute path. Under byte comparison any volatile field restales every artifact forever. Exactly: `<metadata><visimark sheet="<id>" chart="<name>"/></metadata>`.
- Line endings are normalised to LF before comparison and on write.
- Fixed rendering constants: viewBox width `640`; default aspect `16:10`; monospace advance `0.6em`; fills evenly spaced `#333333` → `#CCCCCC` (single series `#808080`), each channel rounded half-up; all strokes and text `#808080`; stroke width `1`.
- Verbatim messages:
  - `chart` as a bound name or column header → `` `chart` is a keyword ``
  - document-scope block → `` `chart` must be in a `#id` sheet block ``
  - table-less sheet → `a chart needs a table`
  - expression operand → `a chart takes a column, not an expression`
  - unknown engine → `` unknown chart type `<word>` `` + did-you-mean
  - malformed aspect → `` aspect needs two positive integers, as `16:9` ``
  - no image line → `` no image reference for this chart — add `![...](path)<!--vmark=<sheet>.<name>-->` ``
  - stale → `` artifact is out of date — run `visimark fmt` ``
  - absent → `` artifact missing at `<path>` ``
  - unowned target → `` `<path>` exists and was not generated by visimark ``
  - path collision → `` two charts write to `<path>` ``
  - chart used as a value → `a chart is not a value`
  - negative pie → `` pie of `<col>` contains a negative value (<v>, row <n>) ``
  - zero-sum pie → `` pie of `<col>` sums to zero ``
  - blank cell → `` `<col>` contains a blank cell (row <n>) ``
  - empty column → `` `<col>` has no rows ``
  - non-numeric series → `` `<col>` needs numbers ``
- Every commit ends with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`. The repo's `Protect master` ruleset requires **signed commits**; sign them or the PR cannot merge.
- After each task: `bun test`, `bun run typecheck`, `bun run build` from the repo root, plus `bun run packages/visimark/src/cli/main.ts check` on every example document. Loop check → fix → check until green. Never `bunx visimark` — that runs the published build, not the branch.
