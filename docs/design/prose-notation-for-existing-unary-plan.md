# Prose notation for unary vocabulary — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to work this plan task-by-task. Steps are checkboxes for tracking.

**Goal:** Per [`docs/design/prose-notation-for-existing-unary-spec.md`](prose-notation-for-existing-unary-spec.md), let a document write `|x|` for `ABS(x)`, `⌊x⌋` for `FLOOR(x, 1)`, `⌈x⌉` for `CEILING(x, 1)` and `√(x)` for `SQRT(x)`. Each resolves to an existing `Call` node before any other stage runs, so no new finding code, no entry in `FUNCTIONS`, and no change to the evaluator, `fmt`, `infer`, `ref` or `--json`.

**Architecture:** One new module, `lang/notation.ts`, holds the glyph tables. The lexer maps `Σ ∑ √` to identifier tokens (the shipped `Σ` mechanism, generalised) and emits a new token kind `delim` for `| ⌊ ⌋ ⌈ ⌉`. The parser gains one table-driven `nud` case for `delim` that requires the pair's closer and returns a `Call`, supplying the literal step `1` for `⌊ ⌈` with the closing glyph's span. A `|` in operand position opens and after an operand has no binding power, which is why `|` nests with no lookahead. `FnDoc` gains an optional `prose` field that the generators, the playground reference panel and the editor hover render. LSP hover stops assuming a call's name is `name.length` wide.

**Tech Stack:** TypeScript; Bun test runner; packages `packages/visimark` (engine) and `packages/visimark-lsp`.

**Spec:** [`docs/design/prose-notation-for-existing-unary-spec.md`](prose-notation-for-existing-unary-spec.md)

### Task 2: the parser

**Files:**
- Edit: `packages/visimark/src/lang/parser.ts` — add `case "delim"` to `nud`, importing `DELIM_PAIRS` and `DELIM_OPENER_OF`:
  - an opener not in `DELIM_PAIRS` (`⌋`, `⌉`) throws `LangError` `` `⌋` has no opening `⌊` `` (spec §4) at that token;
  - otherwise `inner = this.parseBp(0)`; the next token must be `delim` with `value === pair.close`, else `LangError` `` expected `<closer>` `` at that token (an end-of-expression token for an unclosed pair);
  - build `Call { name: pair.fn, args: [inner, ...(pair.step ? [num(pair.step) spanned by the closing token] : [])], start: opener.start, end: close.end }`.
  - extend the leftover-token message in `parseTopLevel` so a `delim` reads `` unexpected `<glyph>` ``; leave every other branch of that message alone.
  - `LEFT_BP` is not touched: a `delim` after an operand has no binding power, which is what ends the inner expression and makes nesting work.
- Test: `packages/visimark/test/lang/parser.test.ts`.

**Interfaces:**
- Produces: `parseExpr("|a - b|")` deep-equals `parseExpr("ABS(a - b)")` ignoring spans; `parseExpr("⌊a⌋")` is a `FLOOR` call whose `args[1]` is `num("1")` with the span of the `⌋`; `parseExpr("||a - b| - 1|")` is `ABS(ABS(a - b) - 1)`.
- Consumes: Task 1's `notation.ts` and `delim` tokens.
